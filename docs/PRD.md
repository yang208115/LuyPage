版本：v0.2 草案

## 1. 产品定位与待确认假设

LuyPage 是一个以图标卡片呈现网站收藏、支持拖拽整理和自定义布局的视觉导航网页。核心价值是：**把常用网站摆成自己顺手的导航首页，看图标就能找到，点击即可访问。**

用户已明确：首页侧重“视觉导航：图标卡片、拖拽、自定义布局”，首版供本人使用、收藏私有，登录后跨设备同步，采用 Cloudflare 托管方案。技术架构保留 R2，按用户预计 2026 年 12 月可用安排接入；该时间不构成发布日期或已通过线上验证的承诺。

| 决策 | 当前方向 | 状态及影响 |
| --- | --- | --- |
| 首页重点 | 视觉导航：图标卡片、拖拽、自定义布局 | 用户已确认；属于首版核心能力 |
| 使用对象 | 本人使用，收藏私有 | 用户已确认；首版不开放注册 |
| 数据保存 | 登录后保存到服务端，支持跨设备访问 | 用户已确认 |
| 部署方向 | Cloudflare 托管，保留 R2 | 已确定方案方向；具体资源与运行验证见技术架构 |
| 内容类型 | 保存网站链接及用户填写的信息 | 建议；不保存网页正文或离线快照 |
| 产品语言 | 简体中文 | 建议；首版不提供多语言切换 |

如果后续改变为“仅当前浏览器保存”，需要调整账号、跨设备同步和数据恢复章节；如果扩展到“公开导航页”或“团队共用”，则需要另行定义发布与权限流程。

## 2. 用户与使用场景

主要用户是经常使用在线工具、阅读技术资料、收集参考网站的人。

| 场景 | 用户问题 | 期望结果 |
| --- | --- | --- |
| 发现一个实用网站 | 链接散落在聊天记录和浏览器标签中 | 粘贴链接即可保存，整理可以稍后进行 |
| 再次寻找资料 | 只记得部分标题、域名或用途 | 输入关键词，快速定位收藏 |
| 整理长期积累的链接 | 同一主题的网站混在一起 | 用分组建立目录，用标签补充用途 |
| 使用常用工具 | 每次都需要重新搜索或翻找 | 从置顶区域直接打开 |
| 布置自己的首页 | 收藏展示顺序和密度不顺手 | 拖动卡片与分组，调整网格密度并保存布局 |
| 从浏览器迁入 | 已有大量书签，逐条添加成本高 | 导入书签文件并明确知道哪些条目成功 |
| 更换设备或迁出 | 担心收藏丢失或无法带走 | 登录继续使用，随时导出自己的数据 |

## 3. 首版目标与范围

### 3.1 产品目标

1. 完成“添加卡片 → 拖拽整理 → 按图标识别或搜索 → 打开”的完整使用闭环。
2. 用户不必先创建分组或标签，就能保存第一条收藏。
3. 每次保存、修改、删除、导入都有明确结果，失败时保留可重试的信息。
4. 收藏数据可以导出，并通过受支持的格式重新导入。
5. 桌面与手机浏览器均可完成核心操作；拖拽不是调整顺序的唯一方式。
6. 用户可调整卡片顺序、分组顺序和网格密度，重新进入页面后布局保持一致。

### 3.2 功能优先级

P0 是首版验收范围，P1 是后续候选项。个人私有及跨设备场景已经确认，账号和同步相关能力纳入 P0。

| 优先级 | 功能 | 范围 |
| --- | --- | --- |
| P0 | 账号与私有收藏 | 登录、退出、会话失效提示；架构采用 Cloudflare Access，具体身份提供方与会话配置待定 |
| P0 | 收藏管理 | 添加、编辑、打开、移入回收站、恢复、永久删除 |
| P0 | 图标卡片首页 | 分组卡片网格、常用区、网站图标与本地回退图标 |
| P0 | 拖拽整理 | 组内卡片排序、跨组移动、分组排序、常用区排序 |
| P0 | 自定义布局 | 网格列数、卡片密度、分组折叠、布局预览与保存 |
| P0 | 分组 | 单层分组、改名、调整顺序、删除、移动收藏 |
| P0 | 标签 | 一条收藏可有多个标签；创建、改名、删除、筛选 |
| P0 | 搜索与筛选 | 关键词、分组、标签、置顶条件组合使用 |
| P0 | 置顶与排序 | 常用收藏；手动排序与按添加时间、修改时间、标题排序 |
| P0 | 批量操作 | 移动分组、添加或移除指定标签、移入回收站 |
| P0 | 导入与导出 | 浏览器书签 HTML 导入导出、LuyPage JSON 导入导出 |
| P0 | 跨设备一致性 | 保存状态、重新获取数据、冲突提示 |
| P0 | 响应式与基础无障碍 | 手机操作、键盘操作、可辨识的焦点和错误提示 |
| P1 | 自动获取网页信息 | 尽力获取标题和描述；失败仍可手动保存 |
| P1 | 个性化外观扩展 | 列表视图、深浅主题、自定义背景、上传自定义图标 |
| P1 | 更快的收集入口 | 浏览器扩展、系统分享入口、快捷收藏工具 |
| P1 | 收藏维护 | 失效链接检查、相似收藏提示 |

### 3.3 首版不做

- 团队空间、成员角色、多人协作编辑。
- 公开分享页面、社交关注、推荐信息流。
- 网页正文抓取、全文搜索、离线阅读、网页截图归档。
- AI 摘要、AI 自动分类、语义搜索。
- 多级目录、像素级自由画布、卡片任意跨行跨列尺寸、天气时钟等额外组件。首版自定义布局采用规则网格。
- 自动双向同步浏览器原生书签、离线修改队列、原生客户端。
- 付费订阅、广告及运营后台。

## 4. 信息架构与页面

### 4.1 页面结构

```text
登录页（采用账号方案时）
└── 导航首页
    ├── 常用区（置顶收藏）
    ├── 分组卡片区（全部收藏）
    ├── 未分组
    ├── 我的分组
    ├── 标签筛选
    ├── 编辑布局
    ├── 回收站
    └── 设置
        ├── 分组与标签管理
        ├── 导入与导出
        └── 账号与退出登录
```

### 4.2 视觉导航首页

- 桌面端：侧边栏提供分组定位，顶部放搜索、“添加收藏”和“编辑布局”，主区域按分组展示卡片网格。
- 首页顶部为“常用区”，下方按自定义顺序展示分组；“未分组”固定在分组区域末尾。未置顶任何收藏时不展示空的常用区。
- 常用区是原收藏的快捷入口，同一收藏可同时出现在常用区及所属分组；修改同步生效，统计只计一条。
- 卡片突出图标与标题，域名为辅助信息；备注和完整标签在详情或编辑面板中查看，避免首页信息过密。
- 标题过长时截断，键盘聚焦、桌面悬停或打开详情时可查看完整标题。
- 浏览模式下点击卡片主体打开网站；更多操作独立；编辑布局模式下卡片用于整理，不触发外链跳转。
- 图标使用网站图标、内置图标或域名首字母回退；图标失败不会留下破损图片或影响打开链接。
- 手机端保留搜索、添加和编辑布局入口，分组导航收进抽屉；默认两列，按可用宽度适配，保证卡片和按钮可触达。
- 搜索或筛选后切换为结果卡片网格，展示结果数和条件，不重复展示常用区；此时不能拖拽改变首页布局。
- 搜索词、筛选、排序保存在页面 URL 中，刷新或返回可还原；首页布局单独保存。

### 4.3 必备页面状态

| 状态 | 页面行为 |
| --- | --- |
| 首次使用、没有收藏 | 说明用途，提供“添加第一条收藏”和“导入书签” |
| 分组为空 | 提供向当前分组添加收藏的入口 |
| 搜索或筛选无结果 | 展示当前条件，提供清除条件操作 |
| 正在加载 | 显示加载状态，不将其误显示为空列表 |
| 加载失败 | 保留已有内容（如果有），提供重试 |
| 保存失败或断网 | 保留表单输入，说明未保存，提供重试 |
| 会话过期 | 提示重新登录；恢复会话前不清空当前表单 |
| 数据被其他设备修改 | 提示存在更新，允许查看最新内容后重新编辑 |
| 布局存在未保存修改 | 明示“未保存”，提供保存和取消；离开页面时提醒 |
| 图标获取失败 | 使用内置图标或域名首字母，不将收藏标记为保存失败 |

## 5. 核心功能规则

### 5.1 添加与编辑收藏

最短添加路径：点击“添加收藏” → 粘贴网址 → 保存。

| 字段 | 规则 |
| --- | --- |
| 网址 | 必填；仅接受 HTTP/HTTPS；明确展示校验错误 |
| 标题 | 可编辑；未填写时以域名作为默认标题 |
| 备注 | 可选纯文本，用于说明用途或保存原因 |
| 分组 | 可选；默认“未分组”；从某个分组内添加时默认选中该分组 |
| 标签 | 可选；支持选择已有标签或创建新标签 |
| 置顶 | 默认关闭 |
| 图标 | 默认尝试获取网站图标；可改用内置图标，失败时使用域名首字母 |

- 输入没有协议的有效域名时，可以补全 `https://`，保存前显示完整地址。
- 不接受 `javascript:`、`data:`、`file:` 等地址，也不执行导入内容中的脚本。
- 含用户名或密码的 URL 不予保存，并提示使用不含凭据的地址。
- 保存中避免重复提交；只有服务端确认成功后才显示“已保存”。
- 编辑失败时保留用户输入；取消存在未保存修改的表单时提示确认。
- 打开收藏使用独立标签页；手机端遵循浏览器行为，不要求弹窗权限。
- 首版不承诺自动标题、描述、预览图或站点可访问性检测。

**重复判断：**仅在同一账号内判断。去除首尾空白，按标准 URL 解析结果规范化协议、域名和默认端口；保留路径大小写、查询参数及其顺序、片段，不擅自删除跟踪参数或尾斜杠。

- 同一规范化 URL 的有效收藏只能存在一条，重复添加时提供查看或编辑已有收藏的入口。
- 如果该 URL 仅存在于回收站，提示恢复已有收藏，避免无意创建重复记录。
- 修改 URL 时应用相同规则；服务端负责最终去重，并发保存不能产生两条有效记录。

### 5.2 分组与标签

- 一条收藏属于零个或一个分组；“未分组”是系统视图，不能删除或改名。
- 分组只支持一层，用户可调整分组顺序。
- 标签用于跨分组描述主题，例如“开发”“设计”“待研究”。
- 分组名及标签名去除首尾空白后不能为空；同账号、同类型名称按不区分大小写判重。
- 删除分组前显示受影响数量；确认后收藏转为“未分组”，收藏本身不删除。
- 删除标签只移除关联关系，不删除收藏；标签改名后全部关联收藏同步展示新名称。
- 提议上限：标题 200 字符、备注 2,000 字符、分组名与标签名各 40 字符、每条收藏 20 个标签、URL 8,192 字符；前后端校验口径保持一致。

### 5.3 查找、筛选和排序

- 搜索范围：标题、URL、备注和标签名称；首版采用普通文本匹配，不提供语义搜索。
- 搜索不区分英文大小写；按空白拆分的多个关键词使用 AND，每个关键词可匹配不同字段；连续中文视为一个关键词。
- 搜索词、当前分组、置顶条件、标签筛选之间使用 AND。
- 同时选中多个标签时使用 AND，即收藏必须包含全部选中标签；界面显示“包含全部所选标签”。
- 清除搜索词只清除关键词，不重置分组和标签；“清除全部条件”回到全部收藏。
- 首页默认使用分组顺序和组内手动顺序；新收藏默认追加到目标分组末尾。
- 分组视图和搜索结果可切换添加时间、修改时间、标题排序；切换不会改写已保存的手动顺序。
- 搜索结果中的置顶项排在普通项前，两部分内部使用同一种排序；常用区有独立手动顺序。
- 普通搜索不包含回收站；回收站使用独立搜索入口和结果。

### 5.4 批量管理与回收站

- 支持多选当前加载列表中的收藏；“全选”明确显示本次选择数量，不隐式选择尚未加载的结果。
- 搜索、筛选或分组变化时清空选择，避免对不可见项误操作。
- 批量修改标签采用“添加指定标签”或“移除指定标签”，保留其他已有标签。
- 批量移动或删除后显示成功数量和失败数量；失败项保留可重试入口。
- 普通删除进入回收站，可恢复；首版不会按时间自动清空回收站。
- 恢复时若原分组已删除，放入“未分组”；仍存在的标签关联继续保留。
- 永久删除与清空回收站必须二次确认，并明确影响数量及无法恢复。
- 遇到恢复冲突时提示用户处理，不静默覆盖已有收藏。

### 5.5 导入与导出

**导入流程：**选择文件 → 解析并预览统计 → 确认导入 → 查看结果。

- 支持常见浏览器导出的 Netscape Bookmark HTML，以及带格式版本的 LuyPage JSON。
- HTML 中的嵌套文件夹在预览阶段映射为单层路径名称，例如“工作 / 前端”；映射冲突或超过名称限制时，要求用户调整映射后再导入。
- HTML 保留可解析的标题、URL、文件夹归属和添加时间；不承诺不同浏览器私有字段的兼容性。
- JSON 保留有效收藏的标题、URL、备注、分组、标签、置顶状态、图标选择、添加及修改时间，以及分组顺序、卡片顺序、常用区顺序和布局偏好；网站图标缓存不打包，导入后可重新获取。
- 同账号内的重复 URL 默认跳过；回收站中的同 URL 条目单独计数并提供恢复入口，不自动恢复。
- 同一文件内部按相同规则去重；不覆盖已存在收藏的备注、标签或分组。
- 无效链接逐项跳过并给出原因；文件无法解析或 JSON 版本不兼容时，在写入前终止。
- 导入结果展示总条目、成功、重复跳过、回收站重复、无效、写入失败及未处理数量，合计应与总条目一致。
- 导入中断后可查看已经完成的结果，重新导入时通过去重安全补齐；不得误报全部成功。
- 建议首版单次导入最多 5,000 条收藏；HTML 文件上限 10 MB。JSON 暂定 512 MiB，采用分片上传及增量处理；字段上限推导和验证要求见技术架构第 9.3 节。上限必须覆盖本应用在该记录规模下生成的合法导出，保证迁出后能够迁回；超限在写入前说明原因。

**导出规则：**

- HTML 面向迁移到浏览器，包含有效收藏的标题、URL、分组；导出前说明备注、标签及置顶等信息无法完整保留。
- JSON 面向 LuyPage 数据迁移，保留上述扩展字段并写入格式版本。
- 两种格式默认导出当前账号全部有效收藏，不受当前搜索与筛选影响；回收站内容不在导出范围内，操作前明确说明。
- 不导出凭据或会话；导入其他账号时重新建立数据归属，不信任文件中的用户 ID。
- 导入空账号时可恢复 JSON 中的布局；导入非空账号默认保留当前布局、新分组和新收藏追加到末尾。只有用户在预览中明确选择“应用文件中的布局”时才替换布局偏好，不删除账号中已有数据。
- 导出失败须提供重试，不生成被误认为完整数据的空文件。

### 5.6 账号与跨设备一致性

本节采用已确认的“个人账号 + 服务端保存”方案。部署方向为 Cloudflare，技术架构采用 Cloudflare Access；具体身份提供方与会话配置在接入时确定。

- 用户只能读取和修改自己的收藏、分组、标签及回收站数据。
- 服务端返回的结果是保存成功依据；刷新后已确认保存的内容仍存在。
- 其他设备在刷新、重新进入页面或页面重新获得焦点时拉取最新数据；首版不要求实时推送。
- 编辑携带版本信息；其他设备已修改同一条记录时拒绝静默覆盖，并保留当前输入供用户对照。
- 离线时明确显示连接异常，允许保留尚未提交的表单；首版不提供离线写入与后台同步。
- 退出登录后清除当前会话中的私有数据展示；切换账号不能短暂显示上一个账号的内容。
- 登录方式必须具备明确的会话恢复或重新认证路径，确定后补充具体登录失败和恢复流程。

### 5.7 拖拽与自定义布局

**布局能力：**

- 首版采用规则卡片网格；桌面端提供自动及 4/5/6 列偏好，手机端提供自动及 2/3 列偏好。实际列数受最小卡片宽度限制，不能产生横向溢出。
- 提供舒适、紧凑两种卡片密度；可调整用户分组顺序、组内卡片顺序、常用区顺序，并折叠指定分组。
- 常用区固定在顶部，未分组固定在末尾；不允许把系统区域拖动成普通分组。
- 桌面与手机列数分别保存；卡片顺序、分组顺序、密度和折叠偏好共用。采用账号方案时这些设置随账号同步。
- “恢复默认布局”提供预览和确认：列数改为自动、密度改为舒适、分组全部展开，用户分组和组内卡片按创建时间从早到晚排列；常用区按收藏创建时间从早到晚排列。该操作不删除收藏或改变分组归属。

**交互与保存：**

1. 点击“编辑布局”进入整理模式，显示拖动手柄、落点和保存/取消按钮。
2. 支持组内拖动排序、跨分组拖动移动、用户分组排序和常用区内部排序；设为常用或取消常用通过独立操作完成。
3. 空分组仍提供可见放置区域；拖向折叠分组时提供展开和落点反馈；拖到无效区域不改变数据。
4. 移动端只在整理模式通过手柄拖动，正常浏览仍可滚动；同时提供“前移/后移”和“移动到分组”操作，键盘用户使用相同替代操作。
5. 修改先在页面预览，点击“保存布局”后整体保存顺序、偏好及本次跨组移动；保存失败保留草稿，不能仅保存其中一部分却提示成功。
6. 点击取消还原进入整理模式前的状态；切换到搜索、离开整理模式或关闭有修改的页面时提醒保存或放弃。
7. 其他设备改变相关收藏、分组或布局导致版本冲突时，拒绝覆盖，提示重新加载最新布局；保留当前草稿供对照，不自动覆盖对方修改。

整理模式与批量操作、收藏编辑互斥，切换前先处理未保存布局；重新获得页面焦点时不能用后台刷新覆盖布局草稿。

**图标规则：**

- 收藏保存成功后异步尝试获取网站图标；图标获取不阻塞收藏保存，也不以能否获取图标判断网址有效性。
- 支持关闭自动获取，并为单条收藏选择内置图标；手动选择优先于自动结果。
- 自动获取仅面向允许访问的公网 HTTP/HTTPS 目标，缓存结果；超时或没有可用图标时立即回退。允许用户保存的内网地址仍使用本地图标，不由服务器探测。
- 获取过程不携带用户浏览器 Cookie，不调用额外第三方图标服务；需限制响应大小、类型及重定向，并校验每次实际连接目标，防止访问内网服务。

## 6. 核心用户流程

### 6.1 首次使用

进入应用 → 登录 → 查看空状态 → 粘贴网址并保存 → 在“未分组”中看到图标卡片 → 点击卡片打开网站。

### 6.2 日常查找

进入导航首页 → 根据常用区或分组中的图标识别网站 → 点击打开；收藏较多时输入标题片段或域名 → 筛选结果 → 打开目标网站 → 返回时保留筛选条件。

### 6.3 整理收藏

进入编辑布局 → 拖动卡片排序或移动到其他分组 → 调整分组顺序及网格密度 → 保存布局 → 退出整理模式后点击卡片访问。大量整理时进入多选，批量移动分组或修改标签。

### 6.4 迁入与迁出

导出浏览器书签 → 上传文件 → 预览数量与分组映射 → 确认导入 → 查看成功和跳过明细；需要迁出时选择 HTML 或 JSON 并下载。

## 7. 核心数据概念

本节定义产品需要保存的信息，不限定数据库或框架。

| 对象 | 关键数据 | 约束 |
| --- | --- | --- |
| 用户 | 标识、认证关联、创建时间 | 不预设具体登录提供方 |
| 收藏 | 标识、所属用户、原始与规范化 URL、标题、备注、分组、置顶、组内顺序、常用顺序、图标选择、创建时间、修改时间、删除时间、版本 | 每条记录归属一个用户；版本用于并发冲突处理 |
| 分组 | 标识、所属用户、名称、顺序、创建时间 | 单层；删除不级联删除收藏 |
| 标签 | 标识、所属用户、名称 | 同用户内名称唯一 |
| 收藏与标签关系 | 收藏标识、标签标识 | 多对多，且必须属于同一用户 |
| 首页布局 | 所属用户、桌面及手机列数、密度、折叠分组、版本 | 按用户保存，跨端按各自视口应用 |
| 导入结果 | 所属用户、处理状态、条目统计与错误明细 | 用于解释部分成功和失败；不长期保留上传原文件 |

回收站是收藏的一种状态，不建立另一套无法同步的收藏副本。创建与修改时间统一保存绝对时间，在界面按用户所在时区显示。

## 8. 非功能需求

### 8.1 性能与容量

- 首版按单用户 5,000 条有效收藏、100 个分组、500 个标签设计和验收；这是测试基线，不是已经验证的能力或最终商业配额。
- 建议验收环境：中等配置桌面设备及手机、20 Mbps 网络、100 ms 往返延迟，记录实际浏览器和设备。
- 上述基线下，首次进入导航首页至可操作目标不超过 2 秒；查询防抖不超过 200 ms，发出查询至展示结果的 P95 目标不超过 500 ms。图标异步加载，不阻塞首页交互。
- 列表分页或渐进加载，避免一次渲染全部收藏；加载更多失败时保留已经显示的内容。
- 拖拽排序以稳定记录标识和真实相邻项为依据，不能把当前加载片段误当成整个分组；无论是否分批加载，都提供移动到分组及移动到首尾的替代操作。
- 导入显示真实处理进度或已处理数量，不能用无法对应实际任务的假进度；最终指标需在实现后实测。

### 8.2 隐私、可靠性与可访问性

- 所有读写、导入导出及批量接口校验用户身份和数据归属，不能只依赖前端隐藏入口。
- 收藏、备注及导入文件内容按数据处理，不作为 HTML 或脚本执行。
- 日志记录必要的错误信息与操作标识，默认不记录完整收藏 URL、备注、导入原文件或凭据。
- 首版仅为网站图标进行受限网络获取，不抓取正文；遵守 5.7 的关闭开关、公网访问校验、超时与缓存规则。
- 部署方案需要明确数据库备份和恢复流程；JSON 导出是用户迁移能力，不能代替服务端恢复方案。
- 核心功能覆盖 360 px 手机宽度与常见桌面布局，无阻碍操作的横向滚动。
- 所有按钮提供可读名称；弹窗管理焦点，支持键盘提交与关闭；状态不只依靠颜色表达。
- 浏览器验收目标为发布时的 Chrome、Edge、Firefox、Safari 稳定版，以及 Android Chrome、iOS Safari；实际验证范围在交付时记录。

## 9. 首版验收标准

| 编号 | 验收场景 | 通过条件 |
| --- | --- | --- |
| A01 | 首次添加 | 仅输入合法网址即可保存，默认标题和未分组状态正确，刷新后仍存在 |
| A02 | 网址校验 | 无效地址、危险协议和含凭据地址被拒绝，输入不丢失，错误可理解 |
| A03 | 重复与并发添加 | 同账号相同规范化 URL 不产生重复有效收藏；重复请求返回可处理结果 |
| A04 | 修改收藏 | 标题、备注、URL、分组和标签正确保存；失败可重试且不误报成功 |
| A05 | 分组与标签管理 | 改名反映到相关收藏；删除分组或标签不删除收藏 |
| A06 | 组合检索 | 搜索字段、关键词 AND、多标签 AND、置顶条件与排序符合约定 |
| A07 | 批量操作 | 数量与实际选择一致；保留未指定修改的标签；部分失败可识别与重试 |
| A08 | 删除与恢复 | 删除后进入回收站；恢复可找回；永久删除有确认且无法再次恢复 |
| A09 | HTML 导入 | 文件夹映射可预览，重复、无效和失败项有明细，统计与实际写入一致 |
| A10 | JSON 往返迁移 | 导出后导入空账号，所有有效收藏及扩展字段、图标选择、排序与布局正确保留；容量基线内的合法导出可重新导入 |
| A11 | 两种导出 | 导出范围不受筛选影响；明确格式损失和回收站排除规则 |
| A12 | 数据隔离 | 账号 A 无法通过替换对象标识或批量请求读取、修改、导出账号 B 的数据 |
| A13 | 跨设备与冲突 | 两个会话中保存后重新获取可见；旧版本提交不会静默覆盖新版本 |
| A14 | 异常恢复 | 断网、服务错误和会话失效有明确反馈，不清空输入或展示虚假的成功状态 |
| A15 | 手机与键盘 | 手机上可完成添加、查找、编辑和恢复；核心操作可通过键盘完成 |
| A16 | 容量与性能 | 在约定数据规模下实测加载和查询，报告设备、环境和达标情况 |
| A17 | 图标卡片 | 标题、域名和操作清楚；图标失败自动回退；手动图标选择不被后续自动结果覆盖 |
| A18 | 拖拽整理 | 组内、跨组、分组和常用区排序正确；无效落点不改数据，空分组可接收卡片 |
| A19 | 布局保存 | 预览、取消、保存及恢复默认符合规则；刷新或另一设备重新获取后布局一致 |
| A20 | 布局异常与替代操作 | 保存失败保留草稿，冲突不静默覆盖；手机及键盘用户无需拖拽也能完成整理 |

## 10. 实施顺序与待决策事项

### 10.1 建议实施顺序

1. **确认范围：**保留已确认的视觉导航、个人私有、跨设备及 Cloudflare 方向，细化认证配置和存储约束，冻结首版 P0。
